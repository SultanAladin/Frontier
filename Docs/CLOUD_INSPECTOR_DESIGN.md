# Clouds inspector · observatory UI

The cloud redesign is limited to the **global Clouds inspector**. The subsequently approved Sun redesign opts into the same scoped observatory component styles, with its own warm colourway; the Clouds design is otherwise unchanged. The shell, viewport, outliner, local-cloud inspector, other environment inspectors, renderer, shaders and baking cards are not restyled.

## Implemented

`Source/CloudInspectorDashboard.js` and scoped `Style/CloudInspector.css` provide:

- **Overview:** density atlas generated by the existing cloud-density worker, requested coverage, formation label, layer base/effective top, GPU cloud-pass duration, and a direct coverage × density editor with numeric entry.
- **Formation:** current renderer density-envelope profile, formation selector, altitude/thickness/ceiling, scale, erosion, anvil and light response. The existing layer-stack editor remains available in a disclosure.
- **Rendering:** calculated target-pixel share and extent, thickness-aware sample count, resolution-footprint diagram, trace budgets and existing ground-shadow controls.
- **Weather:** shared-wind controls/navigation, local-cloud placement and the existing lightning/thunder card.

All prior global cloud settings remain editable. Native `C.Notify` / `C.Synchronise` integration is retained; controls mutate the existing renderer settings and use its persistence path. Numeric fields clamp to the existing `CloudRanges`; count fields round to integers. Keyboard-accessible tabs and direct graph edits do not require a pointer. Cloud density preview workers still terminate through the inspector's existing disposer lifecycle. No extra render loop, GPU pass or per-frame data readback is added.

## Data semantics

- Coverage is a **setting**, not measured sky coverage.
- The atlas is a **static density diagnostic**, not a lit sky render; the crosshair/grid is an annotation, not an additional sensor.
- The formation curve uses `CloudProfile` from existing density diagnostics; its envelope is not measured opacity.
- Base/top/depth use actual ceiling clipping; the rendering tab uses `CloudExtent` and `CloudSkySamples`.
- Pixel share is `(resolution / 100)²`, not a predicted speedup.
- GPU time is the renderer's existing **smoothed** Cloud pass timing, not a fabricated history or instantaneous measurement. Unavailable/uninitialised timing is shown as an em dash rather than a false zero.

## Interactive input refinement

The data-focused layout now also pairs each dashboard numeric setting with a full-width rounded drag slider, using the existing `ConstructSlider` mechanics via `ObservatorySlider`. Percent controls retain their internal 0–1 setting scale; bounds, integer budgets and base/ceiling linkage still pass through `SetCloudDashboardValue`. Clouds keeps its accepted atlas/navigation while varying instrument surfaces: a gridded mix pad, gradient layer profile, open light-response section, technical render-budget card, asymmetric shadow card and dashed ForceField connection. Atmosphere has its own separate optical-workbench stylesheet, not a Clouds recolour.

`Tools/AtmosphereInspectorBrowserProof.mjs` verifies real pointer drags on Cloud coverage and edge erosion, including displayed-percent/internal-value synchronisation.
