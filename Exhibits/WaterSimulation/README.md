# Water Simulation — validation evidence

Retained validation for `Experimental/WaterSimulation/` (2.5D grid water, grid foam, GPU spray particles,
three switchable 3D water models). Everything here is generated by the scripts in `Validation/` and does not
replace the prototype itself.

## Environment for this run

| Item | Value |
|---|---|
| Host | Linux sandbox, Debian 12, x86‑64, no GPU and no display |
| Node.js | v22.22.3 |
| Browser | none available (headless Chromium cannot launch: missing system libraries, no network for apt) |
| GLSL validator | `glslangValidator` built locally from the shaderc source shipped inside `pyshaderc` 1.1.3 |
| Revision | branch `arena/f2993b80-frontier`, working tree with the prototype added (uncommitted at run time) |
| Native renderer | untouched — no Vulkan/Slang code was changed |

🔴 **No GPU frame was rendered on this host.** The prototype has been executed only through its shader
compilation path, a stand-in WebGL2 recorder, and CPU reference re-implementations. A real browser run on your
machine is the remaining verification step, and it is the only check that can confirm appearance.

## Reproduce

```bash
cd Exhibits/WaterSimulation/Validation
node RunAllValidations.mjs            # all scripts, transcripts written to ../Results/
node ShaderStageValidation.mjs        # shader stages only (needs glslangValidator)
```

Shader-stage validation needs a `glslangValidator`. If it is absent the script exits with status 2 and reports
`BLOCKED` rather than passing. Point `GLSLANG_VALIDATOR` at the binary, or rebuild it:

```bash
python3 -m venv /tmp/shadenv && /tmp/shadenv/bin/pip install cmake ninja
/tmp/shadenv/bin/pip download --no-deps --no-binary :all: -d /tmp/sd pyshaderc
# extract the bundled shaderc zip, then patch two files for a modern toolchain:
#   third_party/spirv-tools/utils/update_build_version.py   open(..., mode='rU') -> mode='r'
#   third_party/spirv-tools/source/validate_cfg.cpp         add #include <limits>
/tmp/shadenv/bin/cmake -B/tmp/sdl -H<_cffi_build>/shaderc -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_POLICY_VERSION_MINIMUM=3.5 -DCMAKE_POSITION_INDEPENDENT_CODE=ON \
    -DSPIRV_SKIP_EXECUTABLES=ON -DSHADERC_SKIP_TESTS=ON -DENABLE_GLSLANG_BINARIES=ON
/tmp/shadenv/bin/cmake --build /tmp/sdl --config Release --target glslangValidator -- -j8
```

### Defects this validation found and fixed

| Defect | Symptom | Fix |
|---|---|---|
| Spectral normalization was `1/N²` | Model 1 waves would render ~65 000× too flat (RMS 0.000 m in test) | Removed the factor; the butterfly output already is the Tessendorf wave sum |
| Weak sine hash for the Gaussian realization | Reconstructed RMS 33 % under target; correlated neighbouring cells | PCG integer hash (`HashCell`) in `SpectrumInitialize.frag` |
| No variance calibration | Even with the correct normalization the discrete reconstruction kept only ~50 % of the variance | `MeasureReconstruction` measures survival per cascade and compensates the scale |
| `bitfieldReverse` used for FFT indices | Not available in GLSL ES 3.00 — the shader would fail to compile in every WebGL2 browser | Explicit `ReverseBits` loop in `Common.glsl` |
| `FractalNoise` used with no `Noise.glsl` include | `WaveFieldStep.frag` failed validation: no matching overload | Added the include |
| Chunk keyed without `.glsl` suffix | First runtime boot threw "missing shader chunk" | Registered chunks by full file name |
| Vessel heading and stern offsets | Boat would travel stern-first and the wake would trail ahead of the hull | Corrected yaw target and local +Z mapping |
| Vertex-only program `FullscreenVertex` registered | Boot aborted in the browser: WebGL2 cannot link a program without both stages | Entry removed; `CompiledProgram` rejects stage-less descriptors; harness now emulates the LINK_STATUS rule |
| Transform-feedback program had no fragment stage | Same link failure once the first entry was removed | `TransformFeedbackIdle.frag` attached (never rasterized) |
| Ripple and sea grids shared texture unit 0 | Both grids would sample the same texture, so ripples or the sea solve would be silently wrong | Sea grid on unit 0, ripple grid on unit 1 |
| Height atlas never bound the terrain atlas | Spray collision and vessel buoyancy would read whatever texture unit 12 last held | `TerrainAtlas.Bind` added to the height-atlas pass |
| FFT resolve/slope uniforms set on a stale program | Uniform values belong to the bound program; the spectral model would run with default constants | Every `Use()` now happens immediately before that program's uniform block |

## Not verified here

- 🚩 Browser appearance, frame rate, and interaction on a real GPU (no display/GPU in this host).
- 🚩 Windows execution of `Launch.bat`.
- 🚩 Behaviour on GPUs without `EXT_color_buffer_float` (the page refuses with a notice rather than degrading).
- 🚩 Transform-feedback particles were exercised through the recorder only; no GPU readback of particle state.
- 🚩 No performance measurements. The cost column in the prototype README is a design rating, not a measurement.
